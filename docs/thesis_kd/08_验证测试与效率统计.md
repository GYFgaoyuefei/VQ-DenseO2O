# 验证、冻结评价和效率口径

训练每个 epoch 在 Mixed Validation 上验证原生 EMA 的独立 FP32 副本，关闭 autocast 和 TF32。DDP 验证在副本中同步 rank 0 的 EMA buffers。原生 COCO 评价器计算逐图匹配，新命名空间的派生评价器在跨 rank 汇合时对图片 ID 和对应评价张量一起排序、去除补齐样本。评价前确认 selection 对应的协议和 SHA256；将论文用教师、尺度、λ 和 checkpoint 全部冻结之后，单独运行 evaluate-test。该命令写入冻结选择记录，随后同 run 的 resume 将被拒绝。Test 仅在这个显式入口读取。

```bash
run=outputs/thesis_kd/feature_kd_ms_v1/study01/s_kd/seed_42
python -m thesis_kd.cli validate --run-dir "$run" --device cuda
python -m thesis_kd.cli evaluate-test --run-dir "$run" --device cuda --confirm-frozen
bash scripts/thesis_kd/autodl/benchmark_one.sh s_kd 42
```

可提供 `--illumination-map 路径.json`，按与当前数据集对应的图像 ID/名称映射处理光照子集。缺少合法光照证据或无可用样本时，汇总保留缺项状态。原始预测和评价报告保存在相应 evaluation_val 或 evaluation_test 子目录。

正式速度测量先确认没有其他 GPU 训练负载，再显式执行以下命令。T0 路径从同一标记的指定教师资源读取。默认 benchmark 只产生非正式 smoke 数据。

```bash
python -m thesis_kd.cli benchmark --run-dir "$run" --device cuda:0 --exclusive-gpu
python -m thesis_kd.cli benchmark --teacher --run-tag study01 --device cuda:0 --exclusive-gpu
```

正式协议采用 PyTorch eager FP32，batch=1，GPU 驻留全零 [1,3,640,640]，每轮 warmup 100 次、记录 500 次，共 5 轮，每次同步 CUDA 并计 wall-clock 时间。计时包含部署 detector 与 tensor postprocessor。排除数据传输、增强、磁盘、Teacher/KD 和 Criterion。FPS=1000/对应平均延迟(ms)。记录设备、软件版本、逐次耗时、参数和 FLOPs 统计器覆盖情况。FLOPs 使用同一 detector profiler 及算子规则，和包含后处理的 latency 有各自范围；不支持算子保留覆盖标记。摘要会检查同架构参数和 FLOPs，以及跨结果的统计协议。正式 GPU 结果目前为 NOT RUN。
