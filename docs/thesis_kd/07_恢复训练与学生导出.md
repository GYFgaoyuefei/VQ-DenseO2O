# 恢复、选模与原生导出

正式 run 的目录形式为 `outputs/thesis_kd/feature_kd_ms_v1/<tag>/<experiment>/seed_<n>`。训练保存完整的 epoch 边界状态为 last_training.pth，选择最好的学生 EMA 为 best_student.pth。selection.json 包含 Mixed Validation AP、epoch、种子、协议及最佳权重 SHA256。同分保留较早的 epoch。完整训练 checkpoint 和部署参数字典有不同的加载入口。

```bash
run=outputs/thesis_kd/feature_kd_ms_v1/study01/m_kd/seed_42
python -m thesis_kd.cli resume --checkpoint "$run/last_training.pth" --device cuda
python -m thesis_kd.cli validate --run-dir "$run" --device cuda
python -m thesis_kd.cli export-student --run-dir "$run"
```

resume 重建原生学生、EMA、当前启用的投影、优化器和学习率函数，严格核验教师身份、学生/协议、步数及参数分组等，再装入每个 rank 保存的状态。需要相同的 world size 与匹配的 Train/Val 资源；KD 还需要原 T0。checkpoint 保存 detector、EMA、projectors、AdamW、GradScaler、调度计数、成功更新与已处理 batch 进度和各 rank 可保存的随机状态。失败更新不推进 EMA 或 KD warmup。数据 worker 的预取队列、Mosaic 缓存和进行中的 batch 无法还原，恢复粒度为 epoch 边界。

输出 `student_deploy.pth` 是已绑定的原生参数字典，默认导出到同一 run。新进程使用对应官方 M 或 S YAML 构造三分类学生，禁用 backbone 的初始化文件读取后 strict=True 装载。以 S 为例，使用包含原生 engine 的仓库即可。

```python
import torch
from engine.core import YAMLConfig

cfg = YAMLConfig("configs/deimv2/deimv2_dinov3_s_coco.yml")
cfg.yaml_cfg["num_classes"] = 3
cfg.yaml_cfg["DINOv3STAs"]["weights_path"] = None
model = cfg.model.float().eval()
weights = torch.load("student_deploy.pth", map_location="cpu", weights_only=True)
model.load_state_dict(weights, strict=True)
```

要输出 COCO category_id，在该新进程中同时设置 postprocessor.category_ids 为 [1,2,3] 并关闭 remap_mscoco_category。部署融合仅在独立推理副本上执行。
