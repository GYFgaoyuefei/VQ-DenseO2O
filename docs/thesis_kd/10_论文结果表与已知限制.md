# 论文表与缺项解释

```bash
python -m thesis_kd.cli summarize --run-tag study01 --split val
python -m thesis_kd.cli summarize --run-tag study01 --split test --teacher-result /path/to/T0_test.json
```

同一 tag 的 summary/val 与 summary/test 分别生成 paper.csv、per_seed.csv、paired_ap.csv 和 training_cost.csv。per_seed 保留 Seed、TeacherID、ProtocolID、RunTag；paper 保留 Model、Epoch、Params(M)、GFLOPs、Latency(ms)、FPS、Hardware、Mixed 的 12 个 AP/AR 指标和 Natural / Artificial / Low-light / Sodium-light AP。延迟和 FPS 来自正式 benchmark；没有测量时单元格留空。逐种子表保留消融和敏感性运行，核心论文表使用 T0 和四个学生组。

每个学生报告 0、42、3407 三个训练种子的原始值、算术均值和样本标准差（分母 n−1）。同架构的同种子配对差值为 KD AP% 减 Base AP%，单位是百分点。种子不齐保留单次记录及缺项状态。训练成本单独列出总训练时间、最大显存和实际更新数。

T0 的 `--teacher-result` 是指定单个 checkpoint 的实测结果 JSON。填写 checkpoint_sha256、teacher_id（哈希/权重分支）、validation_basis、split、epoch、annotation_sha256、illumination_map_sha256（无外部映射可用 null）及 metrics 映射。metrics 使用与逐种子表相同的 16 个百分数表头。若该 tag 下已有 T0 的正式 benchmark，摘要验证教师身份一致后才引用效率字段。没有真实数据时，相应性能行标记 NOT RUN。不要用旧 VQ 三个种子的均值代填 T0，也不要混用不同选模方式或 FLOPs 覆盖口径的结果。

目前无正式训练或 Test/效率测量数值。初始 λ=1、公共 AdamW、5 epoch KD warmup 及 continuous_no_rollback 是协议设定，是否改善 AP 需要冻结设计后的实测。权重、确认资源和已完成验收见第 09 章。
