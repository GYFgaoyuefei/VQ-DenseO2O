# 源码模块与配置说明

## 1. 入口与调用关系

- train.py → YAMLConfig → resolve_innovation：解析环境变量、验证独立开关、选择已注册组件。
- instance_mask_sync → VisibleMaskCocoDetection → sidecar校验/实例元数据 → torchvision同步几何/共享sanitize → BatchImageCollateFunction。
- li_copyblend → BatchImageCollateFunction.apply_mixup 的原 CopyBlend 时间分支 → LICopyBlend。MixUp与CopyBlend保持原互斥调度。
- gr_vq → GRVQDEIMCriterion → 原 DEIMCriterion.forward → 显式监督分支 get_loss → gr_vq_quality → 原 MAL。
- dc_sta → DINOv3STAs.forward → DCSTA 对 STA details 门控 → 原 concat/1×1/SyncBN。
- tools/paper_v2/run.py → 真实 train.py 子进程 → DetSolver → 真实 CocoEvaluator。

配置均以 configs/tomato/paper_v2/common.yml 共享原生 DEIMv2-L include。没有复制整套训练框架，也没有继承历史 common_validation.yml 的旧算法开关。

## 2. 独立开关矩阵

|配置|instance_mask_sync|gr_vq.enabled|li_copyblend.enabled|dc_sta.enabled|Criterion|
|---|---|---|---|---|---|
|baseline_native (B0)|false|false|false|false|DEIMCriterion|
|baseline_maskaware (B1)|true|false|false|false|DEIMCriterion|
|gr_vq (G1)|true|true|false|false|GRVQDEIMCriterion|
|li_copyblend (L1)|true|false|true|false|DEIMCriterion|
|dc_sta (D1)|true|false|false|true|DEIMCriterion|

逻辑开关位于 innovation 下，由 resolver 转换成已注册构造器参数。训练集按矩阵加载 mask；Validation/Test 使用原 bbox 数据路径，不为评估加载 mask。DC在数学上不要求mask，但D1遵从实验设计打开同步路径。GR/LI在mask关闭时可读报错。旧 vq_dense_o2o 字段不接受。

## 3. 共同配方

三个类别，COCO IDs [1,2,3]显式映射为分类标签[0,1,2]，输出恢复COCO IDs。若真实类别ID不同，应同时更新 dataset.category_ids 和 PostProcessor.category_ids，经 preflight 验证。

输入640；120 epochs；种子0/42/3407；AMP+EMA；全局train batch32、val batch64；AdamW lr5e−4、DINO lr1.25e−5、betas(.9,.999)、weight_decay1.25e−4，原norm/bias分组保留。新增门控由未匹配参数组或已有sta/bias匹配规则纳入优化器。

实际生效调度是原 FlatCosine：warmup2000 iterations、flat_epoch60、no_aug14、最小LR比例0.5。MultiStepLR/LinearWarmup配置作为原框架构造兼容保留，epoch训练由FlatCosine控制，不叠加两个调度。

增强起止以零基epoch表示：0–6初始停用指定强增强；7–59启用Mosaic(.5)/MixUp(.5)窗口；CopyBlend(.5)窗口7–105；106–119最终no_aug。CopyBlend仅在该step未走MixUp时尝试。area_threshold100、num_objects3、with_expand=true、expand_ratios[.1,.25]、base_size_repeat3均共用。

## 4. 数据契约

sidecar版本 visible-mask-sidecar-v1，coco_annotation_sha256 必须是实际 instances_train.json 的SHA256，annotations以字符串annotation ID为键，记录 image_id/category_id/segmentation/visible_mask_valid；segmentation支持COCO polygon/RLE。该匹配检查只针对训练标注，不扫描仓库。

图像级字段 image_id、idx、orig_size、size、padding、image_illumination_id、image_is_train、li_copyblend_stats 不按实例过滤。实例级字段包括 boxes、labels、masks、visible_mask_valid、annotation_ids、visibility_group、area、iscrowd、source_illumination_id、illumination_source_id、source_is_train、mixup、blend_opacity、keypoints。额外tensor字段按实例长度识别，新增图像级字段应加入 IMAGE_FIELDS。

mask无效只使valid=false；不能删除合法bbox。共享sanitize保留原bbox有效性判据，补齐所有实例字段过滤。B0也获得area/iscrowd同步修复，RGB/bbox/class策略不变。B1原生CopyBlend仍允许矩形混合；mask只是二值支持元数据，不宣称是真实遮挡重新标注。原始实例的area遵循原工程的来源标注/增强约定；新增LI实例以实例字段area_from_mask=true标记，area按二值支持计算、不乘opacity，并在后续多尺度缩放时重新计算。原始实例area_from_mask=false，保持原阈值行为。

光照可来自 COCO image 的 illumination / illumination_label / source_illumination_id，或设置 tomato.illumination_map 指向JSON，如 {"123":"natural","train/example.jpg":"low_light"}。必须来自核实记录。未知光照供体在正式A开启时跳过；没有真实metadata时应补映射，不能用图像亮度猜测。

## 5. 兼容性修复

YAML加载器取消可变默认字典，避免先读G1再读B0时开关污染；支持Windows绝对include和UTF-8。PostProcessor新增可选显式COCO类别映射。profiling calflops改为可选延迟导入，缺失时清楚标识FLOPs NOT RUN。AMP使用device.type，避免cuda:0误作autocast类型。DINOv3原始LinearKMaskedBias的NaN占位buffer改成Q/V=1、K=0；checkpoint仍按原key覆盖，没有改预训练权重加载路径。

Paper v2统一修复EMA原lambda捕获构造时decay导致stage修改不生效的问题；五组均采用有效的stage decay，保留原stage重载/递减决策。checkpoint额外保存阶段比较状态和EMA decay/warmup/start进度。非Paper v2默认EMA行为不改动。该公共修复属于五组共同训练协议，比较历史结果时必须注明。

ConvertPILImage/ConvertBoxes/PadToSize增加torchvision新旧transform方法的兼容入口，保留同一变换实现；防止本地torchvision0.22在真实数据流水线中出现NotImplementedError。collate仅在显式data_vis=true时处理可视化目录，普通preflight不会清理该目录。
