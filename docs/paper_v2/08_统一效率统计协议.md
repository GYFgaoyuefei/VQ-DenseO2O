# Paper v2.0 统一效率统计协议

基准：2026-10-17 standard_ablation_test 中的 PyTorch FP32 部署测试。B0、B1、G1、L1、D1 和 C1–C4 均调用 tools/paper_v2/run.py benchmark → efficiency_measure.measure。当前未执行指定硬件的真实效率测试，输出不得当作已测论文指标。

## 固定条件

|项目|固定值|
|---|---|
|GPU|NVIDIA RTX PRO 6000 Blackwell Server Edition；实际名称不符即拒绝|
|Backend|PyTorch eager eval/deploy；原生deploy转换|
|Precision|FP32；autocast=false；matmul/cuDNN TF32=false；float32 matmul precision=highest|
|输入|GPU驻留全零FP32 tensor，[1,3,640,640]；batch=1|
|cuDNN benchmark|false|
|种子|0、42、3407；各自正式训练选中的EMA checkpoint|
|每seed重复|5轮；每轮每个scope均100次预热、500次正式计时|
|计时|每次迭代先CUDA synchronize，再perf_counter；调用完成后再CUDA synchronize、perf_counter|
|主延迟|detector forward + 原生tensor postprocessor，实际串行调用整体计时|
|附加延迟|独立测detector forward；独立测postprocessor，输入为计时外缓存的detector输出|
|后处理|PostProcessor.deploy()；GPU tensors (labels, boxes, scores)，top-k=300，无NMS/TTA|
|排除|IO、预处理、dataloader、H2D/D2H、criterion/loss、GR-VQ训练计算、LI训练增强、COCO evaluator|

每个scope每轮保存500个原始延迟样本及平均值、P50、P95、FPS、峰值GPU memory。P50为样本中位数，P95为排序后ceil(0.95×500)位置的值。重复/seed级P50和P95按同样分层平均规则汇总，不称为合并7500次样本的百分位数。计时包含Python调用与调用后的同步等待，不采用CUDA Events、torch.compile、TensorRT或AMP替代。forward-only和主延迟各自测量，不直接相加。

显存使用torch.cuda.max_memory_allocated，预热后、每个scope正式计时前重置peak；包括GPU常驻模型/输入及该scope需要的缓存输出，输出单位bytes。每seed取五轮峰值的最大值，模型汇总再取三个seed的最大值。计时结束后才执行FLOPs分析，分析开销不进入延迟/显存指标。runtime记录PyTorch、torchvision、CUDA、cuDNN版本和CPU线程等设置，汇总时禁止混合不同环境。CLI默认--threads 2；同一campaign保持一致，并确保GPU无并发训练/评估工作。

## 参数、FLOPs和统计公式

Full Params(M)为deploy转换前detector全部参数（包括冻结参数）/1e6。Deploy Params(M)为转换后参数/1e6。论文主表Params(M)固定采用后者；不包含criterion和训练增强，GR-VQ/LI不产生新推理分支。

所有模型使用calflops分析deploy detector forward，排除postprocessor。记录calflops版本、原始FLOPs/MACs、矩阵乘法计数约定oracle、分析范围、警告及可检查的算子覆盖信息。不用解析估算值填补缺失算子，不混用其他分析器。calflops无法给出完整的未覆盖算子清单；对融合attention等路径的未证明覆盖保留证据，计数标记PARTIAL，不宣称完整精确GFLOPs。工具不可用或分析失败时GFLOPs留空，并记录UNAVAILABLE/FAILED；约定oracle失败时拒绝采用该数值。正式三种子汇总还要求各记录工具版本一致。

令L(s,r)为seed s第r轮500次的平均延迟：

```text
L_seed(s) = mean_r=1..5 L(s,r)
Latency = mean_s in {0,42,3407} L_seed(s)
SD = sqrt(sum_s (L_seed(s) - Latency)^2 / (3 - 1))
FPS_seed(s) = 1000 / L_seed(s)
FPS = 1000 / Latency
```

三个scope分别应用这些公式。FPS不平均逐次、逐轮或逐seed FPS。未满三个seed时保留已测seed记录，论文聚合效率字段为空，并明确未完成状态。

## 正式执行

```bash
cd /root/autodl-tmp/DEIMv2-new
# 完成该run的120e训练，使用其best.pth/selection.json/config_resolved.yml
bash scripts/paper_v2/autodl/benchmark_one.sh gr_vq 42 cuda:0
# 五组×三个种子，顺序执行；不要重复执行已有记录
bash scripts/paper_v2/autodl/benchmark_all.sh cuda:0 independent
# 也可逐个运行组合配置，保持相同程序/条件
bash scripts/paper_v2/autodl/benchmark_one.sh C1 42 cuda:0
bash scripts/paper_v2/autodl/summarize_efficiency.sh
```

--output-dir可指定单个训练run；--efficiency-dir指定整次效率campaign根目录。已有raw记录拒绝覆盖；新的测量campaign使用新目录，避免混入不同环境。正式入口不提供--iterations、--warmup、--repeats覆盖参数；300次和500次记录不能混合。脚本失败即停止，修复缺失资源后只启动尚未测量的model/seed。benchmark不需要读取Train/Validation/Test图片，也不重新读取预训练源文件。

## 结果与原论文表头

```text
outputs/paper_v2/efficiency/
  raw/<model>/seed_<seed>/efficiency.json
  efficiency_by_seed.csv
  efficiency_summary.csv
  efficiency_protocol.json
  paper_efficiency_table.csv
```

raw JSON保存协议、环境、checkpoint身份、五轮逐次数据和FLOPs覆盖证据。checkpoint的文件大小及mtime在加载前与测量后核对，变化则拒绝保存。by_seed保存每seed五轮汇总；summary保存三个seed均值与样本标准差。协议JSON为机器可读固定协议；没有真实记录也可生成空结果和NOT RUN表格。

论文表固定首先输出：Model、Epoch、Params(M)、GFLOPs、Latency(ms)、FPS、Hardware；接着Mixed AP (%)、Mixed AP50 (%)、Mixed AP75 (%)、Mixed AP-S (%)、Mixed AP-M (%)、Mixed AP-L (%)、Mixed AR1 (%)、Mixed AR10 (%)、Mixed AR100 (%)、Mixed AR-S (%)、Mixed AR-M (%)、Mixed AR-L (%)、Natural AP (%)、Artificial AP (%)、Low-light AP (%)、Sodium-light AP (%)。额外效率审计字段只追加在这些原列之后。Epoch记录完整训练长度120；选中checkpoint的0-based epoch另存raw。

独立评估结果用明确的按seed CSV合并，必需Model、Seed列，AP列使用上述原论文名称，所有AP数值均为百分数（例如63.5，而非0.635）。Model可用配置名；不要在该文件混入Validation与Test结果。缺失AP保持空值。显式输入会保留为ap_by_seed_snapshot.csv，后续效率更新继续沿用该快照。

```bash
python tools/paper_v2/run.py summarize-efficiency --ap-csv /absolute/path/test_ap_by_seed.csv
```

汇总过程只读取记录，不执行评估。论文AP也要求同一字段三个seed均有值才形成均值/样本标准差。模型代码：baseline_native=B0，baseline_maskaware=B1，gr_vq=G1，li_copyblend=L1，dc_sta=D1；C1=GR+LI，C2=GR+DC，C3=LI+DC，C4=GR+LI+DC。
