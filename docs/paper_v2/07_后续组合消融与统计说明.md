# 后续组合消融与统计说明

适用分支 `paper_v3.0`、算法套件 `beta_select_algorithms_v1`。本阶段只完成实现与合成验收，未训练正式模型、未读取真实 Test、未产生论文 AP 或指定 GPU 效率数值。

## 训练及选模

九组模型各运行 seeds 0、42、3407，共 27 个独立训练。B1—C4 形成完整 2³ 矩阵，B0 用于确认 mask-only 工程影响；三因素分析使用 B1 为共同受控基线。启动命令见 [05_AutoDL训练命令.md](05_AutoDL训练命令.md)。所有组从共同预训练重新开始，不 resume 旧 GR-VQ 或 residual DC-STA。

统一以 EMA FP32 Mixed Validation AP 选 `best.pth`，关闭 autocast、TF32，精确并列选较早 epoch。不要用 Test 选 checkpoint、调整参数或筛选组合。报告训练轮数 120 和实际选中 epoch 时应区分：配置 `Epoch=120`，选中 epoch 由记录另列。

建议在同一 seed 内计算每个因素相对于对应基线的 AP 差，再报告三 seed 差值的均值和样本标准差。二因素交互可用 `AP(VQ+LI)-AP(VQ)-AP(LI)+AP(B1)`；其余因素同理，三个因素固定在相同水平时比较。原始各组 AP 和缺失情况应同时保留，三个 seed 不足以支持未经检验的显著性宣称。

## Mixed 与四光照 AP

训练全部完成且方案冻结后，才显式执行最终 Test 命令：

```bash
bash scripts/paper_v2/autodl/evaluate_and_summarize_ap.sh cuda:0 all
```

该命令评估九组×三个 seed 的 EMA Validation-selected `best.pth`；默认 `independent` 时只处理五组。Validation 检查可显式追加 `--ap-split validation`，输出到另一个 split 目录。`summarize_results.sh` 主要汇总训练状态与效率；真正计算 Mixed/光照 AP 的入口是上述脚本。已经计算的 AP 只需离线重汇总：

```bash
bash scripts/paper_v2/autodl/summarize_ap.sh --ap-models baseline_native baseline_maskaware vq_dense_o2o li_copyblend dc_sta vq_dense_o2o_li_copyblend vq_dense_o2o_dc_sta li_copyblend_dc_sta vq_dense_o2o_li_copyblend_dc_sta
```

输出为新根目录 `ap/test/` 下的 `ap_by_seed.csv`、`ap_summary.csv`、`ap_protocol.json` 和 `evaluation_attempts.json`，原始 JSON 位于 `raw/<model>/seed_<seed>/`。数值以百分数存储；三 seed 的均值和样本标准差使用 ddof=1。缺失或失败 seed 不补零，三个 seed 不完整时模型汇总值留空；已成功 seed 仍会写 CSV，失败有具体原因并返回非零退出码。

四光照列固定为：Natural AP（自然光）、Artificial AP（人工光）、Low-light AP（微弱光）、Sodium-light AP（钠黄光）。它们是采集光照分组，不是新增检测类别，没有第五个 SI 分组。光照来自已有显式图像标注或已核实的 image_id/file_name 映射；不自动解析文件路径标签，也不能按当前图像亮度推断。若缺少某组，该组不可伪造为 0；查看原始 image_counts 和分组诊断。

保留此前 COCO 兼容修复：有限值负宽高预测传给原生 evaluator，不擅自裁框或改分数；记录数量和示例，非有限数、非法分数或错误 ID 仍拒绝。汇总只接受新套件记录，不把历史同名 Baseline 或 LI 结果接到新表。

## 效率与论文表

```bash
bash scripts/paper_v2/autodl/benchmark_all.sh cuda:0 all
bash scripts/paper_v2/autodl/summarize_efficiency.sh --ap-csv outputs/paper_v2_beta_select_algorithms/ap/test/ap_by_seed.csv
```

全部模型共用已有计时实现：指定 NVIDIA RTX PRO 6000 Blackwell Server Edition；PyTorch eager eval/deploy；FP32、autocast=false、TF32=false；batch=1；GPU 常驻全零 `[1,3,640,640]`。每个 seed 5 轮，每轮每个范围先 warmup100，再正式500次。每次计时前后 CUDA synchronize，用 Python wall-clock。

主延迟直接测 detector forward + tensor postprocessor。forward-only 和 postprocessor-only 分别独立测量，不能相加替代主延迟。每 seed 先求5轮平均，再求3个 seed 的均值和样本标准差；FPS 只能用 `1000 / 对应平均Latency(ms)`。P50/P95 保留；峰值 GPU allocated memory 按范围记录，包含常驻模型/输入。图像读写、预处理、dataloader、CPU/GPU传输、criterion、VQ训练质量计算、LI增强和COCO评估不计入延迟。

效率文件为 `efficiency/efficiency_by_seed.csv`、`efficiency_summary.csv`、`efficiency_protocol.json`、`paper_efficiency_table.csv`。主表列序固定：

`Model → Epoch → Params(M) → GFLOPs → Latency(ms) → FPS → Hardware → Mixed AP及其他Mixed指标 → Natural AP → Artificial AP → Low-light AP → Sodium-light AP`

之后追加标准差、Backend、Precision、Full Params、峰值显存及统计状态。主表 Params 使用 Deploy Params；Full Params 另存。GFLOPs 只统计部署 detector forward，统一 calflops，保留版本、原始计数、口径、覆盖说明和 FMA=2 小矩阵核验。无法证明全部算子覆盖时为 PARTIAL，分析失败则留空，不能宣称精确完整 FLOPs。

## 英文 Efficiency Evaluation Protocol

All nine configurations are evaluated with a single efficiency measurement program following the PyTorch FP32 deployment protocol established in the standard_ablation_test experiments on October 17, 2026. Measurements use an NVIDIA RTX PRO 6000 Blackwell Server Edition GPU, the PyTorch eager evaluation/deployment backend, batch size one, and a GPU-resident all-zero FP32 input tensor of shape 1 × 3 × 640 × 640. Automatic mixed precision and TF32 are disabled. For each training seed (0, 42, and 3407), five repetitions are performed for every timing scope, each consisting of 100 warm-up iterations followed by 500 timed iterations. Latency is measured with Python's high-resolution wall clock, with CUDA synchronization immediately before and after each iteration. Primary latency includes the detector forward pass and the native tensor postprocessor with 300 selected predictions. Detector-only and postprocessor-only latencies are measured independently; their sum does not replace the directly measured primary latency. Image I/O, preprocessing, data loading, host–device transfers, loss computation, VQ-DenseO2O training computations, LI-CopyBlend augmentation, and COCO evaluation are excluded.

For each seed, latency is averaged over the five repetitions, after which the mean and sample standard deviation are computed across the three seed-level means. FPS is defined as 1000 divided by the corresponding mean latency in milliseconds. P50 and P95 are calculated within each repetition using the median and nearest-rank 95th percentile and summarized using the same repetition-then-seed procedure. Peak allocated GPU memory is recorded separately for each timing scope after warm-up and peak-statistic reset, including resident model and input allocations. Full and deployed parameter counts are both recorded; the deployed count is used as Params(M) in the main table. GFLOPs cover only the deployed detector forward pass and are estimated consistently using calflops after latency measurement. The tool version, counting convention, scope, and operator-coverage evidence are recorded. Counts with unsupported or unverified operator coverage are labeled PARTIAL and are not represented as complete, exact FLOP counts. Failed or unavailable estimates are left unreported. Software versions and measurement settings are held constant throughout the campaign.
