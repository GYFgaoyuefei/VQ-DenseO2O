# paper_v3.0 实验配置矩阵

本轮正式方法为 VQ-DenseO2O、LI-CopyBlend、原 Sigmoid DC-STA。配置和工具目录保留 `paper_v2` 名称，开发分支为 `paper_v3.0`，算法套件为 `beta_select_algorithms_v1`。

|代码|正式模型标识|Mask|VQ|LI|DC|
|---|---|---:|---:|---:|---:|
|B0|baseline_native|0|0|0|0|
|B1|baseline_maskaware|1|0|0|0|
|V1|vq_dense_o2o|1|1|0|0|
|L1|li_copyblend|1|0|1|0|
|D1|dc_sta|1|0|0|1|
|C1|vq_dense_o2o_li_copyblend|1|1|1|0|
|C2|vq_dense_o2o_dc_sta|1|1|0|1|
|C3|li_copyblend_dc_sta|1|0|1|1|
|C4|vq_dense_o2o_li_copyblend_dc_sta|1|1|1|1|

前五组配置在 `configs/tomato/paper_v2/<模型标识>.yml`；四组组合在同目录的 `combinations/<模型标识>.yml`。全部只继承同一个 `common.yml`。C1—C4 是论文显示编号，命令行使用完整模型标识。旧 `gr_vq`、`dc_sta_residual` 等标识不再接受。

## 共同训练协议

|项目|有效配置|
|---|---|
|检测器|DEIMv2-L，DINOv3 ViT-S/16，interaction indexes `[5,8,11]`|
|类别|3 个成熟度类别，COCO category IDs `[1,2,3]`|
|训练轮数、seed|120；0、42、3407|
|基本输入、有效 batch|640×640；Train 32，Validation 64；保留原多尺度调度|
|优化器|AdamW；基础 lr=0.0005，DINO lr=0.0000125，weight decay=0.000125|
|学习率|原 FlatCosine；warmup_iter=2000，flat_epoch=60，no_aug_epoch=14，lr_gamma=0.5|
|增强阶段|policy epochs `[7,60,106]`；MixUp `[7,60]`；CopyBlend `[7,106]`，stop=106|
|匹配切换|matcher_change_epoch=88|
|训练数值|原 AMP 训练；所有模型相同|
|EMA|decay=0.9999、warmups=1000；保留当前工程动态 decay 修复|
|选模|EMA FP32 Mixed Validation AP；autocast/TF32 关闭；精确并列保留更早 epoch|
|预训练|全部相同 DINOv3 和 detector 资源，具体路径见 05 文档|
|VQ|所有开启组 beta=0.10，原 MAL gamma=1.5|
|DC|原 sigmoid 门控，初始乘积约 0.999，无 alpha|

B1—C4 的 Dataset、mask sidecar、几何同步与实例字段规则相同；一次加载、一次随图变换。DC 只读取 RGB/特征，不读取 GT mask。VQ 只在 criterion 使用最终 GT mask。只有含 LI 的组启用前景融合，B0/B1/V1/D1 使用原生 CopyBlend；增强调用时段和基础概率一致。

## 配置审计

```bash
python -m tools.paper_v2.run preflight --model all --config-only
python -m tools.paper_v2.run audit-configs
```

本次九组解析 PASS。审计比较实际展开配置的 B0→B1、B1→V1、B1→L1、B1→D1、V1→C1、V1→C2、L1→C3、C1→C4，共八组；没有意外差异。输出目录、实验名、seed 单列管理字段，不作为算法因素。B1—C4 完整覆盖三因素的 2³ 组合。

生成文件：`outputs/paper_v2/config_ablation_matrix.csv`、[ablation_config_audit.md](ablation_config_audit.md)。该 CSV 只是用户指定位置的配置审计，不是旧实验结果；`outputs/` 被 Git 忽略，上传后运行命令可重新生成。

## 独立结果目录

新训练根目录固定为 `outputs/paper_v2_beta_select_algorithms/<模型标识>/seed_<seed>/`。AP 和效率分别进入新根目录的 `ap/<split>/`、`efficiency/`。本次不移动、不重命名旧结果，不接受旧算法记录进入新汇总。即使 B0/B1/L1 的模型名称沿用，也必须重新训练并生成新套件记录；不能仅复制旧结果、修改元数据来混用。
